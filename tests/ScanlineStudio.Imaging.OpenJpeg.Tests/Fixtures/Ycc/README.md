# OpenJPEG 2.5.4 colour-conversion references

Generated by `~/tools/drm-p7a2-colorref/colorref.c` (outside the repo), which compiles the unmodified
`src/bin/common/color.c` of OpenJPEG 2.5.4 (BSD-2-Clause) and links the harness's libopenjp2 2.5.4
(`~/tools/qsstv-drm-harness/deps/openjpeg`). gcc x86-64, `-O2 -std=c99`, `__FLT_EVAL_METHOD__ 0`.

Regenerate (overwrites this folder's `.ycc`, `.jp2`, `.j2k` and `.rgb` files; the pseudo-random inputs
are seeded, so the output is byte-identical):

    cd ~/tools/drm-p7a2-colorref && ./colorref <repo>/tests/ScanlineStudio.Imaging.OpenJpeg.Tests/Fixtures/Ycc

- `*.ycc` — synthetic converter cases. `color_sycc_to_rgb` / `color_esycc_to_rgb` run directly on an
  in-memory image. Little-endian int32: magic `YCC1`, kind (0 sYCC, 1 e-YCC), x0, y0, component count,
  then per component dx, dy, w, h, prec, sgnd, then each component's samples, then a converted flag and,
  if set, the output w, h and the three output planes.
- `*.jp2` / `*.j2k` + `*.rgb` — end-to-end files, lossless, no MCT. The `.rgb` is what the file decodes to
  through opj_decompress's colour-space rule (`opj_decompress.c:1620-1634`) and color.c, then our 8-bit
  mapping: magic `RGB1`, an "is an image" flag, then w, h and w·h RGB byte triples.

Inputs are our own synthetic values. The output of BSD-2 code run on our inputs is used only as test data.
