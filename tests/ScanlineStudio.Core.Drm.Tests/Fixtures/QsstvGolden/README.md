# QSSTV DRM golden vectors

Golden vectors for the DRM/HamDRM port (plan P0). They are generated by `qsstv-drm-harness`, a
standalone C++ CLI that compiles QSSTV's own DRM sources unmodified. The harness lives outside the
repo, at `~/tools/qsstv-drm-harness`. The fixtures are generated output of QSSTV code (GPL-2.0-or-later),
so they need a `LICENSES.md` row.

## Provenance

- **QSSTV source:** local copy `QSSTV-main/` (QSSTV 9.5.11). It is not a git repo; its files are dated 2026-03-14.
  On 2026-10-16 its `src/drmrx`, `src/drmtx`, `src/dsp` and `src/utils` trees were byte-identical to
  upstream `ON4QZ/QSSTV` branch `main` at commit `de3f862c19e44634f65f9281b20cd10d8d9bed07`.
- **Compiled QSSTV files:** all of `drmrx/*.cpp` except the 4 GUI frames, all of `drmtx/common/**`,
  `drmtx/{drmtx,drmtransmitter,drmparams}.cpp`, `utils/{rs,reedsolomoncoder,jp2io,color,arraydumper}.cpp` and
  `dsp/{downsamplefilter,filter,filters,filterparam}.cpp`. **No QSSTV file is patched.**
- **Shims (harness `shim/`, `harness/stubs.cpp`):**
  - `configparams.h`: the config globals.
  - `dispatcher.h`: the event classes.
  - `QApplication`: synchronous `postEvent`. It calls `setDone()`, which releases the spin-waits at
    `drmrx.cpp:53-56,70-73` and `sourcedecoder.cpp:645-650`.
  - `synthes.h`: captures the final int16 stream at `csoundout.cpp:22`.
  - `hybridcrypt.h`, `ftpfunctions.h`, `ftpthread.h`: FTP/hybrid is excluded.
  - `txwidget.h`, `soundbase.h`, `logbook/logbook.h`: stand-ins for the GUI-layer headers.
  - `addToLog` is compiled out by `QT_NO_DEBUG`, as in QSSTV's release build. `logFile::addToAux` is a no-op.
  - `QDateTime::currentDateTime()` is interposed so the clock is pinned.
- **Stage capture:** `CDRMTransmitter::Run()` (`CDrmTransmitter.cpp:51-86`) is re-stated call-for-call in
  `harness/tx.cpp`, so each module's output can be read between calls. Protected and private members
  are read through standard-conforming accessors; class layouts are untouched. `conv_coded` is
  regenerated by calling the same stateless `CConvEncoder::Encode` on the MLC's `vecEncInBuffer`. The
  returned count equals the buffer size.
- **Dependencies:**
  - OpenJPEG 2.5.4, built from the source tarball of tag `v2.5.4`
    (sha256 `a695fbe19c0165f295a8531b1e4e855cd94d0875d2f88ec4b61080677e27188a`).
    The distro ships 2.5.0, which is not used.
  - Qt 5.15.13: Ubuntu noble `5.15.13+dfsg-1ubuntu1`, with QtCore and QtGui runtime, and qtbase5-dev
    headers and moc.
  - FFTW 3.3.10: `3.3.10-1ubuntu3`, double and single precision.
  - Compiler: g++ 13.3.0, x86-64, with `-O3 -std=gnu++11 -DQT_NO_DEBUG`. There is no `-march`, so the
    build uses SSE2 doubles and no FMA contraction.
  - Generation CPU: AMD Ryzen 7 5800X (sse4_2, avx2, fma). QSSTV plans every FFT with `FFTW_ESTIMATE`.
    FFTW picks codelets at run time by CPU, so other CPUs may differ in the last bits of the FFT-based
    stages (OFDM output, RX demodulation). The stages up to and including `cell_grid` use no FFT.
- **Pinned values:**
  - `HARNESS_UTC_STAMP=20260101120000`, so MOT names are `20260101120000-<name>`. `bsr.bin` is not stamped.
  - The callsign is `PA0TST`. The BSR case sends an empty callsign: QSSTV's BSR FAC carries no
    callsign (bsrform.cpp:51-55 never sets it).
  - Each TX case ran twice. Every stage was byte-identical (`deterministic_rerun`).

## Inputs (`inputs/`)

- `test.txt`: 300 bytes of printable ASCII, with a LF every 40 bytes.
- `card.jp2`: 415 bytes. It is `jp2IO::encode` (QSSTV `jp2io.cpp`, OpenJPEG 2.5.4) of a synthetic
  64x48 RGB card (`card.source.png`). The ratio is derived as in `imageviewer.cpp:1049-1059`, with a
  target of 400 bytes, which gives ratio 23.
- `bsr.txt`: a synthetic BSR body in the shape of `storeBSR` compat output (sourcedecoder.cpp:754-780):
  transport ID, `H_OK`, segment size, the non-consecutive erasures 2 and 5, then `-99`.

## File formats

Every `*.bin.gz` is gzip (mtime 0) of a raw little-endian array. Each case's `manifest.json` gives
`dtype`, `blocks`, `block_size` (or a per-block `block_sizes` list) and the `sha256` of the
uncompressed data.

**dtypes**

| dtype | meaning |
|---|---|
| `bit_u8` | one bit per byte, 0 or 1 |
| `u8` | bytes |
| `i16` | int16 samples |
| `f64` | float64 |
| `c128` | complex: re then im, each float64 |

**TX stages**

| file | content | block |
|---|---|---|
| `rs_coded` | `reedSolomonCoder::encode` output, i.e. the MOT body | 1 |
| `mot_header_segments`, `mot_body_segments` | MOT data groups (`vvbiHeader`/`vvbiBody`), MSB-first bytes | one per segment |
| `msc_packets` | `AudioSourceEncoder` output (packets incl. header and CRC), before dispersal | one per MLC frame |
| `energy_dispersed` | MLC input after `EnergyDispersal` | one per MLC frame |
| `conv_coded` | punctured conv output, levels `j=0..iLevels-1` concatenated (sizes in `mlc_levels`) | one per MLC frame |
| `bit_interleaved` | `vecEncOutBuffer` per level after `CBitInterleaver`, concatenated | one per MLC frame |
| `qam_cells` | MSC QAM cells | one per MLC frame |
| `symbol_interleaved` | `CSymbInterleaver` output | one per frame |
| `fac_bits` | `CGenerateFACData` output: 48 bits per frame, CRC in bits 40-47 | one per frame |
| `cell_grid` | `COFDMCellMapping` output | one per OFDM symbol (`iNumCarrier` cells) |
| `out48k*` | the final int16 48 kHz mono stream: the left channel passed to `synthesizer::writeBuffer`. The right channel is verified all-zero. | one per DRM frame: 19200 samples = 400 ms |

**Frame alignment.** `frames_mlc` is always the number of `out48k`/`fac_bits` blocks plus 1. The Run
loop stops after the MLC has built one more frame than is written out (`MOTSlideShow.cpp:43-47`).

**`manifest.json` also records:**
- `drmTxParams` and the drmTx file name;
- the MOT object name;
- `txTransportID`, and its value at end of transmission;
- `segment_schedule` (`CMOTDABEnc::segmentList`; negative = header segment `-1-k`);
- the cell-mapping parameters;
- `int16_overflow_count`;
- `max_abs_scaled_real`: the largest |real × `rNormFactor`| before `(short)` truncation.

**`out48k` storage**
- **Full stream:** `A0_q4_high_long`, `A1_q4_high_long`, `B0_q4_high_long`, `B1_q16_high_long`,
  `E0_q4_high_long`, `E1_q4_high_long`, so every mode × SO has one full OFDM golden. The RS1-4 and BSR
  cases keep head/tail only: the OFDM stage does not depend on the payload, and their payload side is
  bit-exact through `cell_grid`.
- **Other item-5 cases:** `out48k_head.bin.gz` holds the first 3 frames and `out48k_tail.bin.gz` the
  last 6 frames. `stages.out48k.sha256` covers the whole stream.
- **Remaining matrix combinations** (the 58 full-matrix combinations outside the item-5 list):
  sha256 only. They are still stored bit-exact through `cell_grid`.

**RX (`rx/`)**

The input is the case's own TX stream. It is fed in 4096-sample blocks to
`downsampleFilter::downSample4` and then `drmRx::run`, as in `soundbase.cpp:187-189` and
`rxfunctions.cpp:76-87`. The final partial block is zero-padded, and **8 extra all-zero blocks**
(`--tail-zero-blocks 8`, about 0.68 s) follow it so the receiver can flush. QSSTV's file path would
reuse the stale buffer tail there; that only affects audio after the signal has ended.

- **Frames seen vs sent:** with the tail, 78 of 79 cases see one frame fewer than sent (see the case
  table). Which frame is lost (acquisition at the first sample with no lead-in, or the final frame
  lacking pilot symbols for the 2-D channel estimator, `demodulator.cpp:479-492`) is not yet
  attributed. P5 settles this before comparing frame by frame.
- **`B0_q4_high_long` sees only 40 of 52.** On this clean input, QSSTV's RX loses FAC for frames
  23-24 (`WMERFAC` falls to 2.9), drops sync at stripes 171-176, then resyncs. The file still decodes.
  `B0_q4_low_long`, which has the same MSC, does not do this. It is unmodified QSSTV RX code reacting to
  the FAC cells (only `fac_bits`/`cell_grid`/`out48k` differ between the two cases), not a harness
  fault. **Robustness is not verified:** the RX demodulator is float with run-time FFTW codelets, so
  this may be a knife-edge decision. Before P5, rerun it on perturbed inputs (first 48 kHz sample
  dropped; ±1 LSB dither; 64-sample zero lead-in). If all still give 40, P5 must reproduce it; if
  not, P5 compares frame by frame only up to stripe 170 and asserts that the file decodes.
- **Zero-sample guard:** `drmRx::run` makes an extra `demodulate(resamp_signal,0)` call when
  `input_samples_buffer_request==0` (`drmrx.cpp:63-66`). Per-stripe sampling would then miss the
  state between the two calls. The harness therefore counts this condition before every stripe
  (`zero_input_samples_request_count`), and `make_fixtures.py` asserts that the count is 0. It is 0
  in every case.
- Machine-specific work paths in the manifests are replaced by `<harness-work>/`.

| file | content | stored for |
|---|---|---|
| `rx_stripes_12k.bin.gz` (`f64`) | the 1024-sample 12 kHz stripes, int16 scale | `A1_q4_high_long`, `B1_q16_high_long`, `E0_q4_high_long` only (size budget) |
| `rx_sync.csv.gz` | per stripe: time/freq/frame sync, detected mode, SO estimate, `freqOffset`, `fac_valid`, `WMERFAC` | all cases |
| `rx_frames.csv.gz` | per frame: FAC parameters, callsign, MSC validity, packet CRC/first/last flags, the completed data group (type, segment, last, transport ID, size), segment counters | all cases |
| `rx_msc_bits.bin.gz` | the decoded MSC bits of every frame with `msc_data_valid==1` | all cases |
| `bsr_received_*.bin` | the `prepareFixEvent` payload | the BSR case |

`rx_manifest.json` holds the transport blocks, the saved-file hashes, the GUI events and the
`self_consistency` result. A saved file that differs from the input is kept as `saved_*`.

## Proposed comparison tolerances (P1/P5 confirm these)

| stage | tolerance |
|---|---|
| all `bit_u8` and `u8` stages (packets, dispersal, conv, bit interleaver, FAC, MOT segments, RS) | exact |
| `qam_cells`, `symbol_interleaved`, `cell_grid` | \|Δ\| ≤ 1e-12 per component |
| `out48k` | ±1 LSB after `(short)` truncation |
| `rx_stripes_12k` | double port: \|Δ\| ≤ 1e-9; float port: \|Δ\| ≤ 0.1 int16 units |
| `rx_sync` | discrete fields exact; `freqOffset` \|Δ\| ≤ 0.01 Hz; `WMERFAC` \|Δ\| ≤ 0.1 dB |
| `rx_frames`, `rx_msc_bits`, saved files | exact |

**Why 0.1 for `rx_stripes_12k` in a float port:**
- **Worst case:** the decimator is a 180-tap FIR over int16 input, and the normalized taps have
  ‖h‖₁ = 1.763. A float32 accumulation therefore stays within 180 · 2⁻²⁴ · 1.763 · 32768 ≈ 0.62 int16
  units.
- **Measured, float32 port:** on the three stored stripe sets, a float32 port (float32 taps and
  products, summed in sequence in float32) differs by at most 0.020.
- **Measured, double port:** a double re-implementation with a different summation order differs by
  at most 5.1e-11.
- So 0.1 is 5× the measured float error and well under the worst case.

The `rx_sync` bounds are first proposals for P5's float demodulator. Non-finite values (NaN/Inf)
compare equal only to the same non-finite class. Stripes after the last seen frame (the zero tail)
are not compared, except that they must not produce a frame or a file. QSSTV's own values are float and
are printed to 9 significant digits.

## Case matrix

- **Full matrix** through `cell_grid`: A/B/E × SO_0/SO_1 × 4/16/64-QAM × high/low protection ×
  long/short interleaving, with payload `test.txt` and no RS. Case IDs are `<mode><so>_q<qam>_<prot>_<il>`.
- **`--il`** names what is actually sent. `long` is `drmTxParams.interleaver=0`, which QSSTV's UI
  labels "Short" but which runs `SI_LONG` and sends FAC bit 3 = 0. `short` is index 1, with FAC bit 3 = 1.
- **Item-5 list:**
  - every mode × SO with 4-QAM, high protection and long interleaving;
  - B/SO_1 16- and 64-QAM × both protections × both interleavers;
  - RS1-RS4 on `test.txt`;
  - RS1 on `card.jp2`;
  - `card.jp2` at B/SO_1/16-QAM;
  - `bsr.bin` (`drmTx::sendBSR`).

## QSSTV behaviour observed here (relevant to the port)

- **int16 overflow:** 0 overflows in these cases. The largest |sample| before truncation is in
  `cases.json` (max 28918). P3 still implements x86 `(short)(double)` behaviour explicitly.
- **Self-consistency:** 78 of 79 cases give back the input exactly: 77 saved files plus the BSR
  payload. The exception is the RS1 bug below.
- **RS1 decode bug:**
  - `reedsolomoncoder.cpp:158` reads the surplus byte through a signed `char`, `(int)tr_buf[0]`.
  - When the surplus is 128 or more, `coded_file_size` is too large. QSSTV RX then saves the file with
    trailing bytes: `B1_q4_high_long_rs1` (300 bytes) is saved as 441 bytes, with the first 300 correct.
  - With `card.jp2` (surplus 33), RS1 decodes exactly.
  - This is RX interpretation, so it is not wire behaviour.
- **4-QAM ignores protection** in the MSC chain: high and low give identical packets, coded bits and
  cells. Only the FAC protection bit differs, and with it the cell grid and the audio.
- **`bsr.bin` transport ID:** the ID comes from a static that starts at 2 and advances mod 3 on every
  `SetMOTObject` (`DABMOT.cpp:56,98-102`). End of transmission calls `SetMOTObject` again, so the first
  BSR in a QSSTV process goes 0 → 1. Later BSRs in the same process continue the cycle.
- **BSR FAC callsign:** QSSTV's BSR FAC carries no callsign (bsrform.cpp:51-55 never sets it).
- **MOT ContentType/SubType** is (2,1) in every case.
