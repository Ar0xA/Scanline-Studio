Getting started

Welcome to Scanline Studio

Scanline Studio is a cross-platform amateur-radio application for receiving, preparing, transmitting, organizing, and logging analog SSTV pictures. It is a ground-up rewrite of YONIQ, an MMSSTV fork, with a modern audio, CAT, image, and logbook workflow.

The four main tabs

TabUse it for
ReceiveMonitor audio, decode pictures, inspect sync and signal quality, and act on the current frame.
TransmitChoose an SSTV mode and image, edit the outgoing frame, set identification, and transmit it.
GalleryBrowse automatically saved receptions, search and flag them, add notes, export, and link them to QSOs.
LogbookCreate and edit QSO records, search the log, and import or export ADIF.
Offline by design. Core receiving, editing, transmitting, gallery, and logbook work does not depend on a cloud service. QRZ.com callsign lookup is an optional online feature.

Getting started

What you need

The exact station varies, but a typical on-air setup contains these parts.

  • A Windows, Linux, or macOS computer with Scanline Studio installed.
  • A sound input carrying the radio's received audio.
  • A sound output connected to the radio's transmit audio input.
  • An amateur-radio transceiver suitable for the SSTV activity you plan to use.
  • A legal station licence and operating privileges for your frequency, mode, and location.
  • Optional CAT/PTT control through linked Hamlib, rigctld, or flrig.
RF safety. Test with a dummy load when practical. Start with low transmit drive, watch ALC and SWR on the radio, and follow the radio and interface manufacturers' grounding, isolation, and duty-cycle guidance.

CAT is optional. With None (no radio control) selected, you can still receive and generate TX audio, but you must tune and key the radio outside Scanline Studio.

Getting started

First-time setup

Complete the audio and station steps first. Add CAT control only if you want Scanline Studio to read and control the radio.

  1. Open Options from the main menu.
  2. On Audio, choose the capture device connected to RX audio and the playback device connected to TX audio.
  3. Leave the sample rate at its default unless you have a specific DSP-rate requirement. A measured transmit sound-clock correction belongs in TX clock offset, not Sample rate. Choose the correct stereo capture source if your interface exposes two channels.
  4. On Station, enter your callsign, name, and Maidenhead grid square. These values feed templates and log records.
  5. On General, choose your language and review the storage locations.
  6. If you use CAT, configure and test it on Radio / CAT. See Radio and CAT setup.
  7. Select Save.
Keep the first test simple. Verify receive audio and decode before adding automatic PTT, QRZ.com, forwarding, or advanced DSP changes. This makes faults much easier to isolate.

Header and transceiver controls

  • Frequency and mode show the connected radio's current state. You can request a frequency or supported radio mode when CAT is linked.
  • Favourites recall a stored frequency, mode and filter bandwidth in one action. Use Store current or Edit list… to manage them. See Radio and CAT control for how the bandwidth part behaves.
  • RX level shows live capture level. Avoid a permanently low reading and avoid red clipping.
  • Pwr is the application's TX playback gain—not the operating system's device volume and not the radio's RF power setting.
  • Receiving starts or pauses SSTV search. Capture pauses automatically during a Scanline Studio transmission and resumes afterwards. Its label switches to RX Muted whenever capture is stopped.
  • Stop TX, next to Receiving, cancels an in-progress transmission immediately. It is always visible, regardless of which tab you're on, so it is reachable without switching to the Transmit tab first.

Receiving

Receive your first picture

Scanline Studio normally identifies the incoming mode from its VIS header and fills the image from top to bottom as lines arrive. See Supported SSTV modes for the full list of modes it recognizes.

  1. Tune the radio to the SSTV activity and select the correct sideband and filter.
  2. Confirm the RX meter responds without spending much time in the red clipping range.
  3. Confirm the header's Receiving toggle is on (it starts on by default), then on Receive set Auto-detect to Listening. Both are needed: Receiving controls audio capture, Auto-detect controls whether the decoder searches that audio.
  4. Wait for a valid header. The detected mode, line progress, and incoming image update automatically.

If the sender's header is missing or damaged, use a quick-mode button — in the MODE card on the Receive tab — to force the next decode into that mode. Right-click a slot for Hold this mode, which locks every following reception to it and ignores the sender's VIS header until you select Release, and for Reassign this slot, which points that slot at a different mode.

Actions on the incoming frame

  • Export frame… exports the current image to a location you choose.
  • Abort abandons the current reception and returns to searching.
  • Decode WAV… selects recorded audio and runs it through the decoder again.
  • Copy to TX sends the received picture to the Transmit workspace.
  • Log QSO begins a log entry associated with the reception.
  • Record saves incoming audio for later diagnosis or re-decoding.
Automatic history. Completed receptions are saved as PNG files in the configured RX images folder and indexed in the Gallery. Manual JPEG export quality does not change these history PNG files.

Receiving

Reception controls and telemetry

The Receive tab exposes the decoder's important state without requiring routine DSP adjustment.

Stations heard and worked-before

  • Stations heard is a running list of identification the application has automatically read from FSK or CW sent around other stations' pictures — no action needed from you. Each line shows the decoded identification (a callsign, or a full CW text such as "DE W1AW"), whether it came from FSK or CW, the time in UTC, and the SSTV mode, newest first, up to the most recent 20. Turn FSK or CW decoding on or off in Station identification.
  • Worked before checks the current reception's callsign against your logbook and shows either New station or the band and date of your most recent prior contact with it (with a leading count only once you've logged that callsign more than once). It is a quick heads-up, not a substitute for checking your own log before claiming a new one.

Frame metadata

The FRAME METADATA card next to the incoming picture shows the current reception's Callsign, NR/RST, CW ID, Name/QTH/Grid from QRZ.com, Frequency, Mode/VIS, Started time, and file size, plus a per-frame Note and Flag.

The callsign fills automatically from decoded FSK or CW identification. If it decoded wrongly or not at all, type it into Override callsign, then select Lookup QRZ to pull name, QTH, and grid (requires QRZ.com to be configured in Options).

Sync & slant

  • Source reports whether the decoder is searching, locked, or in AVT training.
  • Slant ppm estimates sound-clock mismatch that would tilt the picture.
  • Re-sync asks the decoder to reacquire line timing.
  • Correct slant redraws buffered lines using the current correction when buffering is enabled.
  • Squelch level changes how strong a signal must be before it is treated as SSTV. Higher settings reduce false decodes but can miss weak signals.

Input chain

  • BPF controls RX band-pass sharpness. Wide is the recommended starting point; sharper filters reject adjacent interference but tolerate less drift. Note that the option named Normal switches the filter off entirely, despite the name — see Decode options, which documents the same setting reached from Options → Decode. A mid-picture change waits until that reception ends.
  • Notch suppresses a narrow interfering tone. Click the spectrum trace to choose its frequency, then switch it on. It is off by default, and it is not remembered between sessions.
  • Leave the notch off unless you can actually see a carrier in the spectrum. It is a narrow filter placed inside the signal band, so it removes picture along with the interference. That trade is worth making against a real carrier and is a pure loss without one. Switch it off again once the interference goes away.
  • AGC gain, buffer, XRUN, and clipping help diagnose the audio path.

DSP

  • AFC switches automatic frequency control on or off. It is on by default. AFC measures the sync tone and shifts the decode back toward its nominal frequency, which corrects a station that is tuned slightly off. Switch it off if you suspect AFC is locking onto interference instead of the signal.
  • The change applies during the current picture. From the next line onward the correction is no longer added, and the tone detectors return to their nominal frequencies. Lines already decoded keep the correction they were given.
  • While AFC is off, the Sync tone row on the Signal quality card shows a dash, because no correction is being measured.
  • AVT mode never uses AFC, whatever this is set to.
Do not tune by numbers alone. If a picture decodes cleanly, avoid changing squelch, BPF, or advanced demodulator settings merely to make a readout look different.

Receiving

Record and re-decode audio

Audio recordings let you retry a marginal reception and preserve evidence for troubleshooting.

  1. Select Record on the Receive tab before or during the signal you want to preserve.
  2. Select Stop recording when finished.
  3. Choose Tools → Decode WAV file… or the frame's Decode WAV… action.
  4. Select the WAV file and monitor the Receive tab as the decoder replays it.

Try a forced quick mode only when you know the transmitted mode and the replay does not acquire it automatically. If the original recording clipped or omitted the signal, re-decoding cannot restore the missing audio.

Transmitting

Transmit a picture

Prepare the picture and radio before keying. The editor produces the exact pixel dimensions required by the selected SSTV mode.

  1. On Transmit, select a mode (see Supported SSTV modes for the full list) or leave mode following on Auto to reply in the last received mode.
  2. Use Browse…, a stock image, a received image, or the blank editor as your source.
  3. Crop, adjust, and add template elements.
  4. Confirm the output device, duration, identification, Pwr level, and radio state; then select the big TRANSMIT button to apply your edits and start sending in one step. With the CAT backend set to None, Scanline Studio sends no keying command — see What you need for keying the radio yourself.

Select Apply instead of TRANSMIT to save the edit without sending it yet — useful for staging a card ahead of time. Apply closes the editor; reopen it with Edit… and select TRANSMIT when you're ready to send.

During transmission, progress shows percentage and remaining time. Select the header's Stop TX button, next to Receiving, to abort — see Tour of the workspace.

Before the first RF transmission. Use Tune and TX safety to establish a clean drive level. Excess audio can cause ALC action, splatter, poor SSTV quality, or automatic SWR cutoff.
Auto mode following. Auto normally matches the last received mode for a reply. It will not make an unsafe mid-transmit change, and it can decline a change when the already loaded image width is incompatible.

While transmitting

The Power/ALC meter shows live PWR, ALC, and SWR readings from the connected radio (when it reports them), plus a tone map showing the audio-frequency range the current mode is using and a TX clock readout — useful for confirming the transmission is actually progressing, not just that time is passing.

Sent frames

A "Sent frames" list on the Transmit tab keeps a short history of this session's transmissions — each with its outcome (Sent, Stopped, or Failed). Select Resend to transmit the same frame again, or Save… to export a copy of it. This history is session-only; it does not persist between application restarts the way the Gallery's receive history does.

Transmitting

Edit the outgoing image

The TX image editor is the main pane of the Transmit tab — there is no separate editor window to open. It combines non-destructive framing, image adjustments, and overlay composition (text, boxes, lines, and extra pictures on top of your base photo, also called the background — see Background vs. backdrop). Its mode-exact preview shows the pixels prepared for transmission.

Frame the base image

  • Use Move, Crop, Scale, and Rotate tools on the canvas.
  • Preserve aspect (letterbox) keeps proportions and fills unused frame space rather than stretching the image.
  • Lock crop to mode constrains the crop rectangle to the selected mode's aspect ratio.
  • Safe area displays a composition guide. It does not crop the transmitted frame.
  • Snap grid snaps an element to a 5% grid after a drag or resize.
  • Use Fit, 100%, and the zoom controls to change only your view of the editor.

Add and arrange elements

The + Text, + Box, and + Line tools place new overlay elements on the canvas; picture elements come from the Insert Image controls covered in Templates, text, boxes, and images, which also covers each element type's own styling in depth.

  • Click an element to select it; Shift-click additional elements on the canvas to select several at once. A multi-selection can be dragged, nudged, duplicated, or deleted together, but not resized, aligned, or restyled as a group — style and geometry changes still apply to one element at a time.
  • Lock an element to stop it from being dragged by accident; Duplicate makes a copy to build a related element quickly.
  • Copy/Cut/Paste move or duplicate elements through the clipboard; Copy Style/Paste Style carry over a text, box, or line element's appearance (color, outline, font, and similar) onto another element of the same type, without touching its position or content — it's greyed out for image elements and when the copied and target types don't match.
  • The right-click menu's Arrange submenu reorders layers — Bring to front, Bring forward, Send backward, Send to back. A separate item on that same right-click menu, Flatten into image, permanently merges one element into the background photo, after which it can no longer be moved or restyled on its own.
  • Undo/Redo cover the editing session.

Background vs. backdrop

These sound similar but are not saved the same way:

  • The background is the one photo the whole frame is built on — loaded via Browse or STOCK on the Transmit tab's sidebar. There is always exactly one; loading a new one replaces it. The background is never saved with a template — a template only stores its overlay elements, so the same template can be reused with a different photo for every contact.
  • A backdrop is an inserted picture element (+ Image) that has been sent to the very back of the layer stack and stretched to fill the frame — the right-click menu's Set as backdrop item does this. Unlike the background, a backdrop IS saved with the template, so it's the way to build a template with a fixed, reusable photo baked into its design (a logo card, a fixed QSL background, and similar).
  • Right-click the empty canvas and select Turn into backdrop to convert the current background into a backdrop element — useful right before saving a template you want to always include a specific photo. This bakes in the current crop and adjustments, then leaves the background blank.
  • Right-click a backdrop element and select Turn into background to convert it back — it replaces whatever is currently loaded as the background and removes the element, immediately, on one click. Undo restores the previous background and the removed element together if you didn't mean to. A backdrop element is locked by design, which can block the canvas's own right-click menu — use the same-named button on its row in the ELEMENTS list (in the docked sidebar) if right-clicking the canvas doesn't show the menu.
  • Right-click the empty canvas and select Remove background to clear the current background photo outright, without keeping it as a backdrop element. Unlike Turn into backdrop, the photo is discarded, immediately, on one click — use Undo to bring it back.
  • At most one backdrop can exist at a time — setting or promoting a new one replaces any previous backdrop automatically.

Adjust the picture

Brightness, contrast, saturation, gamma, sharpen, and denoise are stored with the working template and applied before overlays are drawn. They do not overwrite the original source file.

Finish or discard

  • TRANSMIT — the large, distinctly-colored button — applies the editor state into the prepared TX frame and immediately begins transmission. This is the only way to send a picture; there is no separate Transmit button elsewhere.
  • Apply saves the editor state into the prepared TX frame without transmitting, and closes the editor — for staging a card ahead of time. Reopen with Edit… and select TRANSMIT when you're ready to send.
  • Revert returns to the last applied state.
  • Cancel closes/discards as prompted; a confirmation dialog appears when unsaved edits would be lost.
Preview limit. The preview is accurate for crop, scale, adjustments, and overlay placement. It does not simulate the chroma loss or other color effects introduced by a complete transmit-and-receive path for every SSTV mode.

Transmitting

Templates, text, boxes, images, and lines

Template elements let you build reusable QSL-style layouts on top of the background photo, then save and instantly recall them for future contacts — see Background vs. backdrop for what does and doesn't get saved.

Build a layout

  • Add Text, Box, Line, or Image elements. Image sources include a file, the clipboard, the last received image, and receive history.
  • Select an element in the Elements list or on the canvas, then use the Inspector's Geometry/Text/Image tabs for exact position, size, and appearance.
  • Shift-click additional elements on the canvas to select and move several at once (see Edit the outgoing image for the full selection and layering controls).

Text styling

Text elements can use any bundled font, at a chosen size, bold and/or italic. Beyond plain fill color, you can add an outline (stroke) with its own color and thickness, a drop shadow with an adjustable offset, a "3D stack" repeated-copy effect (its own step-offset controls), a gradient fill, or a picture as the fill instead of a flat color (from a file or the clipboard) — pick whichever combination keeps the text legible over your particular background photo. Select Clear picture fill from the right-click menu, or use the CLEAR button next to the picture fill controls, to remove a picture fill and go back to a flat color.

Resizing a text element's box shrinks the font to keep it fitting by default; growing the box back does not grow the font past its set size. Right-click a text element and turn on Grow to fill box to let the font also grow larger when there's room. It's off by default and per element — turning it on for one text element does not affect any other. The toggle itself is not remembered between edits — it resets to off whenever a template reloads — but saving a template captures the actual grown font size, so a reloaded template still shows text at the size it last grew to, not its original set size.

Box and line styling

Boxes support a fill color or gradient, an optional border with its own thickness, rounded corners, and opacity. Lines support their own stroke color and thickness. Both are plain geometry, not photos, so they composite cleanly over any background.

Perspective transform

Image and box elements can be skewed to a four-cornered shape instead of a plain rectangle — useful for making a flat picture look like it's lying at an angle, e.g. a photo "taped" onto a background at a slight tilt. Turn on Perspective in the element's inspector, then drag its four corner handles on the canvas.

Insert live fields

The Insert Field menu places tokens like his call, his grid, your call, your grid, frequency, mode, UTC time, date, distance, and bearing into a text element — typing once updates every place that token appears. Fields are grouped by where their value comes from:

  • My side — your own callsign, name, and grid from Station options, plus the current date and time. Always available.
  • Radio — live frequency and mode from the connected rig. Shows blank on the transmitted card if no radio is connected.
  • Per-QSO — the other station's callsign, grid, signal report, distance, and bearing. Needs a value typed into the QSO FILL bar first (the row of fields at the top of the TX image editor holding the per-contact values for the card about to be sent), or it shows blank.

See Macros and template fields for the full token reference and how distance/bearing are calculated.

Save and recall templates

  1. Enter a template name and select SAVE. Right-clicking the canvas also offers Save Template — if you've already typed a name it saves immediately with that name, otherwise it auto-fills the next free "tmp1", "tmp2", … name and saves right away; it's disabled when the canvas has no elements to save.
  2. Use the Template Library filter to find saved layouts. Switch between LIST and GRID view with the toggle at the top of the panel (your choice is remembered). Click a row or tile once to select it and reveal its own Load/Pin/Export/Delete buttons plus an editable name field; double-click — or right-click for the same actions as a menu — to load it. A pinned template shows a PINNED badge; select Pin on it to place it in the TEMPLATES rack, the strip of nine slots elsewhere in the TX editor.
  3. In the Templates rack: click a slot once to select it and reveal its own Load/Unpin/Export/Delete buttons plus an editable name field (Enter commits a rename, Esc reverts). Double-click a slot — or right-click it for the same actions as a menu — to load it. Number keys 1–9 still recall a slot directly when the editor owns keyboard focus, the fastest way to reply mid-QSO without touching the mouse at all.
  4. Loading over unsaved work asks first: Discard unsaved changes?, naming the template that would replace them. A slot showing Loaded is the one the canvas currently came from; it reads Loaded • edited once you've changed anything since.
  5. Deleting from the Templates rack asks for confirmation, naming the template and its slot number. Deleting from the Template Library list asks for confirmation too, naming the template.
  6. Use EXPORT to save a single-file bundle you can share with another operator, and IMPORT to load one someone shared with you.
  7. Select IMPORT LEGACY to load a .mtm or .mti template file from a legacy YONIQ/MMSSTV install. Most content (text, position, color, images, boxes) carries over; a few legacy-only effects (multi-stop gradients, dash/decorative line styles, underline/strikethrough, most macro tokens other than the sender's own callsign) have no equivalent here and are approximated or dropped — a status message tells you if anything needed adjustment, and the full detail is in the log.

Transmitting

Station identification

Identification settings are configured in Options → Identification. The top section (Off / CW / Sound file) and the checkboxes below it control what you send; a separate pair of checkboxes controls what the application automatically hears from other stations.

What you send

  • Encode FSK ID on transmit encodes the configured station callsign after the picture when enabled.
  • CW (Morse) sends the configured CW ID text at the selected CW ID tone (Hz) and CW ID speed (WPM).
  • Sound file plays a supported legacy .mmv audio file instead of CW identification.
  • NR/RST can add a configured static sub-packet to FSK ID. It is not automatically filled from the current logbook exchange.

The Transmit tab's Tail summary shows whether the current combination is FSK + CW, FSK + sound file, one method only, or off.

FieldRangeDefault
CW ID textFree textDE %m (sends "DE" followed by your callsign)
CW ID tone (Hz)100–3000 Hz1000 Hz
CW ID speed (WPM)10–50 WPM28 WPM

What the application automatically hears

Two separate checkboxes let Scanline Studio listen for other stations' identification and log it for you, independent of what you yourself send:

  • Decode FSK ID on receive reads FSK identification sent by other stations.
  • Decode CW ID on receive reads Morse identification sent by other stations, opening a listening window (CW ID capture window (seconds), 5–20 seconds, default 12) around each reception.

Anything decoded this way appears in Stations heard on the Receive tab — you don't need to do anything else to see it.

Legal identification remains your responsibility. Confirm that the selected text, callsign, method, and timing meet the rules that apply to your station.

Browse received images

Find a frame

Work with the selection

Images and logging

QRZ.com lookup and UDP forwarding

Both integrations are optional. Configure them in Options only if they are part of your logging workflow.

QRZ.com

  • Enable callsign lookup and enter your QRZ.com credentials under Options → QRZ.com.
  • Use Test to check the credentials.
  • On the Receive tab's Frame metadata card, select Lookup QRZ next to a received callsign to pull name, QTH, and grid — see Reception controls and telemetry.

This screen configures callsign lookup only. The current application does not provide an Options control for QRZ Logbook uploads.

Credential storage. The current application stores the QRZ.com password locally in its settings file without encryption. Use a unique password rather than one reused for other accounts.

ADIF over UDP

Under Options → Forwarding, add each destination's name, host, and port. Every newly logged QSO is sent to enabled destinations as a WSJT-X protocol LoggedADIF message. Common local ports include 2237 for GridTracker and 2333 for some N1MM Logger+ or Log4OM arrangements; use the receiving application's own documentation as the authority for its port.

Radio and audio

Radio and CAT setup

Open Options → Radio / CAT, choose one backend, enter its connection details, test it, save it, and then connect the real radio session. Test connection, Connect, and Disconnect are all on this same tab, below the backend settings — not in the main window's transceiver header.

Once connected, transmit power, the Tune test tone, and the automatic high-SWR cutoff live in a separate topic: see Tune and TX safety.

BackendWhen to choose itMain settings
NoneYou control tuning and PTT outside the application.No connection settings.
rigctldA Hamlib rigctld process or compatible server is already running.Host and TCP port.
Linked HamlibYou want Scanline Studio to load an installed Hamlib library directly.Library, Hamlib rig model number, CAT serial port, baud rate, and PTT method.
flrigAn flrig instance is already controlling the radio.Host and XML-RPC port.

Linked Hamlib sequence

  1. Leave the Hamlib library path blank for normal auto-detection, or browse to a specific shared library. Select Test.
  2. Choose a model from the detected list, or enter Hamlib's numeric model ID.
  3. Select the CAT serial port and baud rate.
  4. Choose PTT: CAT uses the CAT connection; RTS/DTR uses the selected PTT port; VOX sends no keying command and relies on the radio's own audio-triggered VOX.
  5. Run Test CAT and, when applicable, Test PTT.
  6. Select Save, then Connect. Connect uses saved settings, so save newly edited values first.
One controller at a time. Direct serial access commonly fails when another program already owns the port. Use a sharing backend such as rigctld or flrig when multiple applications must work with the same radio.

Filter bandwidth (Transceiver header)

When the connected backend supports it, a small bandwidth control appears on the Transceiver header card at the top of the main window — separate from the Options dialog above. It offers three common quick picks, 1800, 2400, and 2800 Hz, but you can type any other value and select Set to request it. Not every backend supports this — flrig doesn't, since its own bandwidth readback can't be reliably converted to a plain Hz value across different radios.

Too narrow can break the picture. An overly narrow filter can break SSTV decode or clip transmitted audio. The radio may also silently snap your request to its nearest real filter rather than matching it exactly.

Filter bandwidth stored per Favourite

Each Favourite stores its own filter bandwidth alongside its frequency and mode, and applies all three when you select it. This exists because setting the mode makes the radio fall back to its own default filter for that mode, which on some radios is far too narrow for SSTV. The bandwidth is always sent after the mode, for that reason.

The quick picks in the Edit list… dialog follow the mode you choose for that Favourite. SSB and data modes offer 1800, 2400 and 2800 Hz. FM modes offer 9000, 12000 and 15000 Hz. Changing a Favourite's mode between those two groups moves its bandwidth with it. The field stays freely editable, so you can type any value between 50 and 20000 Hz, and a value you type is sent exactly as typed.

A Favourite stored before this feature existed has no bandwidth of its own. It uses 2400 Hz on SSB and data modes, and 15000 Hz on FM modes.

Selecting a Favourite overwrites a filter you set by hand. Backends that cannot set bandwidth, such as flrig and OmniRig, skip that step and leave the radio's filter alone.

Which modes a Favourite can use

The Edit list… dialog offers six modes: USB, LSB, FM, DATA-U, DATA-L and DATA-FM. The DATA modes use the radio's data connector rather than its microphone path, which is normally what you want for soundcard SSTV. Not every radio has DATA-FM.

Modes not used for SSTV — AM, CW and RTTY — are not offered. Store current is unavailable while the radio sits on a mode outside those six, so it cannot create a Favourite the dialog could not then display.

Radio and audio

Tune and TX safety

The Radio / CAT tab includes a controlled tone for setting application playback gain against the radio's own meters.

  1. Use a dummy load or clear test frequency where practical, and begin with low Pwr.
  2. Select Tune. Scanline Studio keys PTT and generates a steady tone for up to 30 seconds.
  3. Slowly raise Pwr while watching the radio's RF power and ALC indications.
  4. Stop before ALC becomes excessive. Select Stop tune or let the time limit stop it.

Stop TX if SWR too high cancels an active transmission after the connected radio reports a value over the chosen threshold for two consecutive polls. The option cannot work if the radio or backend does not report SWR.

Not primary protection. Software polling and CAT can fail or lag. The SWR cutoff is a convenience backstop, not a substitute for the transceiver's hardware protection, a suitable antenna system, or operator monitoring.

PLL demodulator tuning

High cutoff values degrade the picture. The two cutoff fields accept values far above anything useful. Troubleshooting

Start with the visible symptom, change one thing at a time, and preserve a WAV recording or application log when the failure is intermittent.

The RX meter does not move

  1. Check that the header's Receiving toggle is on and Auto-detect on the Receive tab is set to Listening. While Auto-detect is Paused, the waterfall keeps scrolling but the level meter and station-ID decode stop.
  2. Confirm the radio is producing audio and the physical cable is connected.
  3. Re-select the capture device in Options → Audio.
  4. If the device is stereo, test Mono, Left, and Right capture source.
  5. Check OS input permission, mute state, and device routing.

Audio is visible, but no picture starts

  • Confirm Auto-detect says Listening, not Paused.
  • Reduce an overly high squelch level.
  • Use a wider radio receive filter and correct sideband.
  • If you know the mode and the VIS header was lost, force the next decode with its quick-mode button.
  • Record the signal and retry with Decode WAV file.

The image is slanted

  • Enable RX buffering and Auto-slant in Options → Decode.
  • During reception, inspect Slant ppm and use Correct slant after a stable estimate is available.
  • Persistent TX reports about your own outgoing slant may indicate a measured TX clock offset is needed; do not guess the value.

Reception breaks up or XRUN increases

  • Close other applications that heavily use the audio device or CPU.
  • Confirm the USB audio interface has a stable connection.
  • Avoid advanced DSP changes until the audio transport is stable.

CAT or PTT fails

  • Save edited Radio / CAT settings before selecting Connect.
  • Disconnect the active session before running a backend test.
  • Check host/port for rigctld or flrig, and firewall access if it is not local.
  • For linked Hamlib, test the library, model number, serial device, baud rate, and PTT method.
  • Make sure another program has not exclusively opened the serial port.
  • VOX cannot be command-tested: it relies on the radio detecting actual TX audio.

Transmit fails or stops

  • Confirm a playback device and prepared image are selected.
  • Check PTT and radio state with a short controlled test.
  • If the message reports high SWR, stop and inspect the antenna system; do not merely raise the cutoff.
  • Open the application log for the specific error.

A Gallery image will not open

The file may have been moved or deleted outside the application. Select Refresh, check the configured RX images folder, and restore the file from backup if needed.

Dark mode or Large text isn't what you expected

  • Confirm you selected Save on the Appearance tab — both settings apply immediately once saved, but a change left unsaved has no effect.
  • System theme follows your operating system's own light/dark setting, not a fixed choice — pick Light or Dark directly if you want it to stay put regardless of the OS setting.
  • Large is a single fixed size, not a slider — if it feels too big or too small there's no in-between value to nudge it toward, only Normal or Large.

Stations heard stays empty

  • Confirm FSK decode and/or CW decode are turned on in Options → Identification — both are off by default, since decoding is extra work the application only does when asked.
  • Not every station sends identification the application recognizes: a station may be using FSK/CW at a speed, tone, or format Scanline Studio doesn't decode, or may not be identifying by tone at all.
  • The list only fills from stations you actually receive — it isn't a directory of who's active on the band.
Useful support bundle. Note the application version from Help → About, the operating system, selected audio and CAT backend, exact error text, reproduction steps, and the relevant application-log excerpt. Include a short WAV only when it is needed to reproduce a decode issue.

Glossary

Hover or focus a dotted-underlined term anywhere in this guide to see its definition without leaving the page — each one links here, to the same single definition, so it can't drift out of sync with a second copy elsewhere.

ADIF
Amateur Data Interchange Format; the standard file format logging software uses to exchange QSO records.
AFC
Automatic frequency control; measures the received sync tone and shifts the decode back toward its nominal frequency, correcting a station that is tuned slightly off. It corrects mistuning only — it does nothing about noise or interference.
AGC
Automatic gain control; normalizes received signal level for processing.
ALC
Automatic level control; a radio's own circuit that reduces drive when transmit audio would otherwise overdrive the final amplifier.
AVT training
A decoder state for the AVT SSTV mode family, which needs to measure the incoming signal before it can lock onto and decode the picture — distinct from the normal searching/locked states other modes use.
BPF
Band-pass filter; passes a chosen frequency range and rejects everything outside it.
CAT
Computer Aided Transceiver control: frequency, mode, PTT, and telemetry communication with a radio.
DSP
Digital signal processing.
FIR
Finite impulse response; one of two common digital filter designs (see also IIR). Always stable, at the cost of needing more computation for the same sharpness.
FSK ID
Frequency-shift keyed station identification data sent around an SSTV transmission.
Hamlib
A radio-control library and toolset supporting many transceivers.
Hilbert transform
A mathematical technique for recovering a signal's instantaneous frequency; the default demodulator method Scanline Studio uses to turn incoming SSTV tones back into brightness values.
IIR
Infinite impulse response; the other common digital filter design (see also FIR). Cheaper to compute, but can behave less predictably if pushed to extreme settings.
LPF
Low-pass filter; passes frequencies below a chosen cutoff and removes everything above it.
Maidenhead grid
A short letter-and-number code (e.g. JO22) that identifies a location on Earth, used across amateur radio for a compact "where I am" instead of a full address.
NR
A serial/reference number, here the optional numeric sub-packet FSK identification can carry alongside your callsign.
PLL
Phase-locked loop; one of the demodulator methods Scanline Studio can use to track the incoming picture tone and recover brightness from it.
PPM
Parts per million; here, a small audio-clock error that can produce image slant.
PTT
Push to talk; the control that keys the transmitter.
QSO
A radio contact between stations.
QSL
Confirmation of a radio contact; often represented by a designed card or SSTV picture.
RST
Readability, strength, and tone signal report. SSTV exchanges may use related reporting conventions.
SSTV
Slow-scan television: still images carried as audio-frequency tones over a radio channel.
SWR
Standing wave ratio; an indication of impedance mismatch in the RF path.
UTC
Coordinated Universal Time; the single time zone radio operators use to log contacts so records from different time zones stay comparable.
VCO
Voltage-controlled oscillator; the tunable internal oscillator the PLL demodulator uses to track the incoming picture tone.
VIS
Vertical interval signalling: the SSTV header code used to identify the picture mode.
VOX
Voice-operated transmit; the radio keys itself when it detects input audio.
WPM
Words per minute; the speed unit used for CW (Morse code) identification.
XRUN
An audio buffer underrun or overrun, usually indicating that audio data was not handled in time.
