Getting started

Welcome to Scanline Studio

Scanline Studio is a cross-platform amateur-radio application for receiving, preparing, transmitting, organizing, and logging analog SSTV pictures. It is a ground-up rewrite of YONIQ, an MMSSTV fork, with a modern audio, CAT, image, and logbook workflow.

The four main tabs

TabUse it for
ReceiveMonitor audio, decode pictures, inspect sync and signal quality, and act on the current frame.
TransmitChoose an SSTV mode and image, edit the outgoing frame, set identification, and transmit it.
GalleryBrowse automatically saved receptions, search and flag them, add notes, export, and link them to QSOs.
LogbookCreate and edit QSO records, search the log, and import or export ADIF.
Offline by design. Core receiving, editing, transmitting, gallery, and logbook work does not depend on a cloud service. QRZ.com callsign lookup is an optional online feature.

Getting started

What you need

The exact station varies, but a typical on-air setup contains these parts.

  • A Windows, Linux, or macOS computer with Scanline Studio installed.
  • A sound input carrying the radio's received audio.
  • A sound output connected to the radio's transmit audio input.
  • An amateur-radio transceiver suitable for the SSTV activity you plan to use.
  • A legal station licence and operating privileges for your frequency, mode, and location.
  • Optional CAT/PTT control through linked Hamlib, rigctld, or flrig.
RF safety. Test with a dummy load when practical. Start with low transmit drive, watch ALC and SWR on the radio, and follow the radio and interface manufacturers' grounding, isolation, and duty-cycle guidance.

CAT is optional. With None (no radio control) selected, you can still receive and generate TX audio, but you must tune and key the radio outside Scanline Studio.

Getting started

First-time setup

Complete the audio and station steps first. Add CAT control only if you want Scanline Studio to read and control the radio.

  1. Open Options from the main menu.
  2. On Audio, choose the capture device connected to RX audio and the playback device connected to TX audio.
  3. Leave the sample rate at its default unless you have a specific DSP-rate requirement. A measured transmit sound-clock correction belongs in TX clock offset, not Sample rate. Choose the correct stereo capture source if your interface exposes two channels.
  4. On Station, enter your callsign, name, and Maidenhead grid square. These values feed templates and log records.
  5. On General, choose your language and review the storage locations.
  6. If you use CAT, configure and test it on Radio / CAT. See Radio and CAT setup.
  7. Select Save.
Keep the first test simple. Verify receive audio and decode before adding automatic PTT, QRZ.com, forwarding, or advanced DSP changes. This makes faults much easier to isolate.

Getting started

Tour of the workspace

The fixed main window keeps station state at the top and task-specific tools in four tabs below.

Header and transceiver controls

  • Frequency and mode show the connected radio's current state. You can request a frequency or supported radio mode when CAT is linked.
  • Favourites recall stored frequencies. Use Store current or Edit list… to manage them.
  • RX level shows live capture level. Avoid a permanently low reading and avoid red clipping.
  • Pwr is the application's TX playback gain—not the operating system's device volume and not the radio's RF power setting.
  • Receiving starts or pauses SSTV search. Capture pauses automatically during a Scanline Studio transmission and resumes afterwards.
  • Halt stops the active transmission.

Status indicators

CAT linked
The configured radio backend is connected.
TX KEYED
Live PTT state was read back from a connected rig that supports reporting it. Some VOX or DTR arrangements cannot provide this confirmation.
TX ERROR
The last transmit attempt ended in an error or automatic SWR cutoff. It reports the last outcome; it does not permanently lock out the next attempt.
Line, slant, buffer, frames today, log entries
Compact operating telemetry for the current session.

Receiving

Receive your first picture

Scanline Studio normally identifies the incoming mode from its VIS header and fills the image from top to bottom as lines arrive.

  1. Tune the radio to the SSTV activity and select the correct sideband and filter.
  2. Confirm the RX meter responds without spending much time in the red clipping range.
  3. On Receive, set Auto-detect to Listening.
  4. Wait for a valid header. The detected mode, line progress, and incoming image update automatically.

If the sender's header is missing or damaged, use a quick-mode button to force the next decode into that mode. This is not a persistent mode lock; normal auto-detection remains the default.

Actions on the incoming frame

  • Export frame… exports the current image to a location you choose.
  • Abort abandons the current reception and returns to searching.
  • Decode WAV… selects recorded audio and runs it through the decoder again.
  • Copy to TX sends the received picture to the Transmit workspace.
  • Log QSO begins a log entry associated with the reception.
  • Record saves incoming audio for later diagnosis or re-decoding.
Automatic history. Completed receptions are saved as PNG files in the configured RX images folder and indexed in the Gallery. Manual JPEG export quality does not change these history PNG files.

Receiving

Reception controls and telemetry

The Receive tab exposes the decoder's important state without requiring routine DSP adjustment.

Sync & slant

  • Source reports whether the decoder is searching, locked, or in AVT training.
  • Slant ppm estimates sound-clock mismatch that would tilt the picture.
  • Re-sync asks the decoder to reacquire line timing.
  • Correct slant redraws buffered lines using the current correction when buffering is enabled.
  • Squelch level changes how strong a signal must be before it is treated as SSTV. Higher settings reduce false decodes but can miss weak signals.

Input chain

  • BPF controls RX band-pass sharpness. Wide is the recommended normal starting point; sharper filters reject adjacent interference but tolerate less drift. A mid-picture change waits until that reception ends.
  • Notch suppresses a narrow interfering tone. Click the spectrum trace to choose its frequency, then switch it on.
  • AGC gain, buffer, XRUN, and clipping help diagnose the audio path.
Do not tune by numbers alone. If a picture decodes cleanly, avoid changing squelch, BPF, or advanced demodulator settings merely to make a readout look different.

Spectrum and waterfall

Receiving

Record and re-decode audio

Audio recordings let you retry a marginal reception and preserve evidence for troubleshooting.

  1. Select Record on the Receive tab before or during the signal you want to preserve.
  2. Select Stop recording when finished.
  3. Choose Tools → Decode WAV file… or the frame's Decode WAV… action.
  4. Select the WAV file and monitor the Receive tab as the decoder replays it.

Try a forced quick mode only when you know the transmitted mode and the replay does not acquire it automatically. If the original recording clipped or omitted the signal, re-decoding cannot restore the missing audio.

Transmitting

Transmit a picture

Prepare the picture and radio before keying. The editor produces the exact pixel dimensions required by the selected SSTV mode.

  1. On Transmit, select a mode or leave mode following on Auto to reply in the last received mode.
  2. Use Browse…, a stock image, a received image, or the blank editor as your source.
  3. Crop, adjust, and add template elements. Select Apply when the outgoing frame is ready.
  4. Confirm the output device, duration, identification, Pwr level, and radio state; then select Transmit.

During transmission, the button becomes Stop TX and progress shows percentage and remaining time. Halt in the header also stops the active transmission.

Before the first RF transmission. Use Tune and TX safety to establish a clean drive level. Excess audio can cause ALC action, splatter, poor SSTV quality, or automatic SWR cutoff.
Auto mode following. Auto normally matches the last received mode for a reply. It will not make an unsafe mid-transmit change, and it can decline a change when the already loaded image width is incompatible.

Transmitting

Edit the outgoing image

The TX image editor combines non-destructive framing, image adjustments, and overlay composition. Its mode-exact preview shows the pixels prepared for transmission.

Frame the base image

  • Use Move, Crop, Scale, and Rotate tools on the canvas.
  • Preserve aspect (letterbox) keeps proportions and fills unused frame space rather than stretching the image.
  • Lock crop to mode constrains the crop rectangle to the selected mode's aspect ratio.
  • Safe area displays a composition guide. It does not crop the transmitted frame.
  • Snap grid snaps an element to a 5% grid after a drag or resize.
  • Use Fit, 100%, and the zoom controls to change only your view of the editor.

Adjust the picture

Brightness, contrast, saturation, gamma, sharpen, and denoise are stored with the working template and applied before overlays are drawn. They do not overwrite the original source file.

Finish or discard

  • Apply saves the editor state into the prepared TX frame without transmitting.
  • Apply & Transmit prepares the frame and immediately begins transmission.
  • Revert returns to the last applied state.
  • Cancel closes/discards as prompted; a second confirmation is required when unsaved edits would be lost.
Preview limit. The preview is accurate for crop, scale, adjustments, and overlay placement. It does not simulate the chroma loss or other color effects introduced by a complete transmit-and-receive path for every SSTV mode.

Transmitting

Templates, text, boxes, and images

Template elements let you build reusable QSL layouts on top of the base image.

Build a layout

  • Add Text, Box, or Image elements. Image sources include a file, clipboard, last received image, and receive history.
  • Select an element in the Elements list or on the canvas, then use the Inspector for exact geometry and appearance.
  • Use front/back controls to change layer order. Lock an element to prevent accidental movement, or duplicate it to create a related element.
  • Text can use bundled fonts, fill and outline, shadow, 3D stack, rotation, and gradient settings.
  • Boxes support fill, border, opacity, and geometry. Images support fit mode and geometry.

Insert live fields

The QSO Fill and Insert Field controls place values such as his call, his grid, your call, your grid, frequency, mode, UTC time, date, signal report, distance, and bearing into text elements. See Macros and template fields for the available data and fallback behavior.

Save and recall templates

  1. Enter a template name and select Save.
  2. Use the Template Library filter to find saved layouts.
  3. Select Load to recall one. If the current layout has unsaved work, repeat the selection to confirm replacement.
  4. Select Pin to place a favourite template in the Ready Rack. Rack slots can be recalled with number keys 1–9 when the editor owns keyboard focus.

Transmitting

Station identification

Identification settings are configured in Options → Identification and summarized in the Transmit tab.

  • FSK ID encodes the configured station callsign after the picture when enabled.
  • CW (Morse) sends configured text at the selected tone frequency and words-per-minute speed.
  • Sound file plays a supported legacy .mmv audio file instead of CW identification.
  • NR/RST can add a configured static sub-packet to FSK ID. It is not automatically filled from the current logbook exchange.

The Transmit tab's Tail summary shows whether the current combination is FSK + CW, FSK + sound file, one method only, or off.

Legal identification remains your responsibility. Confirm that the selected text, callsign, method, and timing meet the rules that apply to your station.

Images and logging

Browse received images

The Gallery is the searchable history of completed receptions. Select a thumbnail to inspect and manage that frame.

Find a frame

  • Filter by All, Today, Unlogged, or Flagged.
  • Use the search field for mode or note text.
  • Select Refresh to reload the history and Latest to return to the newest frame.

Work with the selection

  • Add a note or flag important frames.
  • Select Export to write a copy in a chosen image format. The General tab's JPEG quality applies when you choose JPEG.
  • Select Open in log to link the frame to an existing QSO or create and link a new QSO.
  • Open the image viewer for Fit/100% zoom, previous/next navigation, clipboard copy, and opening the file location.

The Storage card shows the active image folder, naming convention, and available disk space. By default, history filenames contain a timestamp, mode, and short identifier.

Moving files outside the application. If a history image is moved or deleted in a file manager, the Gallery entry may no longer open it. Use Refresh to reconcile the view.

Images and logging

Log and find QSOs

The Logbook tab stores station contacts alongside receive history in the application database.

Log a QSO

  1. Select New, or use Log QSO from a received frame to prefill available context.
  2. Enter the callsign, UTC start/end, frequency, radio mode, SSTV mode, sent and received reports, and any station details or notes you have.
  3. Select Log QSO. Optional UDP forwarding runs after the local record is saved.

Search and edit

Filter by exact callsign and UTC date range, then select a row to edit it. Choose Save changes to update the record.

ADIF exchange

Use Import… to add records from an ADIF file and Export… to write matching records. A partial-import warning means records already processed may have been added before the bad record was encountered.

Images and logging

QRZ.com lookup and UDP forwarding

Both integrations are optional. Configure them in Options only if they are part of your logging workflow.

QRZ.com

  • Enable callsign lookup and enter your QRZ.com credentials under Options → QRZ.com.
  • Use Test to check the credentials.
  • A received frame with a callsign can request QRZ details such as name, QTH, and grid.

This screen configures callsign lookup only. The current application does not provide an Options control for QRZ Logbook uploads.

Credential storage. The current application stores the QRZ.com password locally in its settings file without encryption. Use a unique password rather than one reused for other accounts.

ADIF over UDP

Under Options → Forwarding, add each destination's name, host, and port. Every newly logged QSO is sent to enabled destinations as a WSJT-X protocol LoggedADIF message. Common local ports include 2237 for GridTracker and 2333 for some N1MM Logger+ or Log4OM arrangements; use the receiving application's own documentation as the authority for its port.

Radio and audio

Radio and CAT setup

Open Options → Radio / CAT, choose one backend, enter its connection details, test it, save it, and then connect the real radio session.

BackendWhen to choose itMain settings
NoneYou control tuning and PTT outside the application.No connection settings.
rigctldA Hamlib rigctld process or compatible server is already running.Host and TCP port.
Linked HamlibYou want Scanline Studio to load an installed Hamlib library directly.Library, Hamlib rig model number, CAT serial port, baud rate, and PTT method.
flrigAn flrig instance is already controlling the radio.Host and XML-RPC port.

Linked Hamlib sequence

  1. Leave the Hamlib library path blank for normal auto-detection, or browse to a specific shared library. Select Test.
  2. Choose a model from the detected list, or enter Hamlib's numeric model ID.
  3. Select the CAT serial port and baud rate.
  4. Choose PTT: CAT uses the CAT connection; RTS/DTR uses the selected PTT port; VOX sends no keying command and relies on the radio's own audio-triggered VOX.
  5. Run Test CAT and, when applicable, Test PTT.
  6. Select Save, then Connect. Connect uses saved settings, so save newly edited values first.
One controller at a time. Direct serial access commonly fails when another program already owns the port. Use a sharing backend such as rigctld or flrig when multiple applications must work with the same radio.

Radio and audio

Tune and TX safety

The Radio / CAT tab includes a controlled tone for setting application playback gain against the radio's own meters.

  1. Use a dummy load or clear test frequency where practical, and begin with low Pwr.
  2. Select Tune. Scanline Studio keys PTT and generates a steady tone for up to 30 seconds.
  3. Slowly raise Pwr while watching the radio's RF power and ALC indications.
  4. Stop before ALC becomes excessive. Select Stop tune or let the time limit stop it.

Stop TX if SWR too high cancels an active transmission after the connected radio reports a value over the chosen threshold for two consecutive polls. The option cannot work if the radio or backend does not report SWR.

Not primary protection. Software polling and CAT can fail or lag. The SWR cutoff is a convenience backstop, not a substitute for the transceiver's hardware protection, a suitable antenna system, or operator monitoring.

Radio and audio

Audio settings

Audio settings determine where SSTV enters and leaves the application.

Capture device (RX)
The input carrying received radio audio.
Playback device (TX)
The output feeding the radio's transmit audio path.
Sample rate
The DSP rate in whole hertz. Saving a change applies it live by briefly reopening capture and ending any current reception. If audio recording is active, application of the change may be deferred until restart.
TX clock offset
A manual correction for a measured transmit sound-clock error. It changes generated tone timing, not the device sample rate. Leave it at zero without a real measurement.
Stereo capture source
Mono mixes both input channels; Left or Right selects only that channel.
Send TX audio to both stereo channels separately
Duplicates transmit output for interfaces that require both channels.
Device names can change. USB audio devices may enumerate differently after moving ports or updating the OS. If levels disappear after a hardware change, recheck both device selectors.

Options reference

Advanced DSP options

These controls expose low-level demodulator and transmit-filter parameters ported from the legacy application. They are intended for measured experiments and diagnosis.

  • PLL demodulator tuning controls VCO gain and loop/output filter order and cutoff. It applies when PLL is selected and during AVT training.
  • Zero-crossing tuning selects IIR, FIR, or no smoothing and exposes output filter values for that discriminator.
  • TX audio filtering enables or adjusts the transmitted band-pass and low-pass stages.
Record the baseline. These settings can make decode or TX audio worse without an obvious error message. Change one value at a time, keep a representative WAV test recording, and use Reset section to defaults if results deteriorate.

Support

Troubleshooting

Start with the visible symptom, change one thing at a time, and preserve a WAV recording or application log when the failure is intermittent.

The RX meter does not move

  1. Confirm the radio is producing audio and the physical cable is connected.
  2. Re-select the capture device in Options → Audio.
  3. If the device is stereo, test Mono, Left, and Right capture source.
  4. Check OS input permission, mute state, and device routing.

Audio is visible, but no picture starts

  • Confirm Auto-detect says Listening, not Paused.
  • Reduce an overly high squelch level.
  • Use a wider radio receive filter and correct sideband.
  • If you know the mode and the VIS header was lost, force the next decode with its quick-mode button.
  • Record the signal and retry with Decode WAV file.

The image is slanted

  • Enable RX buffering and Auto-slant in Options → Decode.
  • During reception, inspect Slant ppm and use Correct slant after a stable estimate is available.
  • Persistent TX reports about your own outgoing slant may indicate a measured TX clock offset is needed; do not guess the value.

Reception breaks up or XRUN increases

  • Close other applications that heavily use the audio device or CPU.
  • Confirm the USB audio interface has a stable connection.
  • Avoid advanced DSP changes until the audio transport is stable.

CAT or PTT fails

  • Save edited Radio / CAT settings before selecting Connect.
  • Disconnect the active session before running a backend test.
  • Check host/port for rigctld or flrig, and firewall access if it is not local.
  • For linked Hamlib, test the library, model number, serial device, baud rate, and PTT method.
  • Make sure another program has not exclusively opened the serial port.
  • VOX cannot be command-tested: it relies on the radio detecting actual TX audio.

Transmit fails or stops

  • Confirm a playback device and prepared image are selected.
  • Check PTT and radio state with a short controlled test.
  • If the message reports high SWR, stop and inspect the antenna system; do not merely raise the cutoff.
  • Open the application log for the specific error.

A Gallery image will not open

The file may have been moved or deleted outside the application. Select Refresh, check the configured RX images folder, and restore the file from backup if needed.

Useful support bundle. Note the application version from Help → About, the operating system, selected audio and CAT backend, exact error text, reproduction steps, and the relevant application-log excerpt. Include a short WAV only when it is needed to reproduce a decode issue.

Glossary

AGC
Automatic gain control; normalizes received signal level for processing.
CAT
Computer Aided Transceiver control: frequency, mode, PTT, and telemetry communication with a radio.
DSP
Digital signal processing.
FSK ID
Frequency-shift keyed station identification data sent around an SSTV transmission.
Hamlib
A radio-control library and toolset supporting many transceivers.
PPM
Parts per million; here, a small audio-clock error that can produce image slant.
PTT
Push to talk; the control that keys the transmitter.
QSO
A radio contact between stations.
QSL
Confirmation of a radio contact; often represented by a designed card or SSTV picture.
RST
Readability, strength, and tone signal report. SSTV exchanges may use related reporting conventions.
SSTV
Slow-scan television: still images carried as audio-frequency tones over a radio channel.
SWR
Standing wave ratio; an indication of impedance mismatch in the RF path.
VIS
Vertical interval signalling: the SSTV header code used to identify the picture mode.
VOX
Voice-operated transmit; the radio keys itself when it detects input audio.
XRUN
An audio buffer underrun or overrun, usually indicating that audio data was not handled in time.
