# DSP Behavioral Divergence Audit — Legacy YONIQ vs Scanline Studio port

**Mode:** ultracode (read-only, three-wave verification)
**Date:** 2026-08-07
**Scope:** All DSP-relevant modules in `src/ScanlineStudio.Core.Sstv`, `src/ScanlineStudio.Core.Audio*` vs
legacy `yoniq-old/YONIQ-main/*.cpp,*.h`.

**Resolution status (2026-08-07)**: all 19 `MATCH_LEGACY` findings fixed (commit `4f6c7b6`). All 4
`PORT-ONLY BUG` findings (#34, #36, #37, #38) also fixed — see inline notes on each row below and
`PROJECT_BRIEF.md` for the implementation detail (#34 ended up fixed via a periodic decoder-restart
mechanism, not the literal `int`→`long` widening this doc originally suggested — plan-readiness review
found that widening had a much larger blast radius than expected). `KEEP_PORT_DEVIATION`/
`NEEDS_MAINTAINER_DECISION` findings remain as documented, no code change intended.

## Methodology

1. **Wave 1** — 10 independent read-only `auditor` agents, one per DSP subsystem. Each read the actual
   legacy source directly (never inferred TX from RX or vice versa), independently re-derived/hand-computed
   candidate divergences, and labeled each `confirmed` or `needs runtime test`.
2. **Wave 2** — 10 fresh, independent `auditor` agents, one per subsystem, each given only the *stripped
   claim* (no severity/confidence from Wave 1) and told to re-derive it from primary source **from
   scratch**. Several Wave-1 claims were refuted or corrected here.
3. **Wave 3** — 7 fresh, independent `auditor` agents asked a different question per surviving finding:
   *is the recommended "make the port match legacy" fix actually porting a legacy bug forward?* Each
   re-verified the cited source lines directly and returned an explicit verdict — **MATCH_LEGACY**
   (legacy behavior is intentional design and the port should replicate it), **KEEP_PORT_DEVIATION**
   (legacy's behavior here is an accidental artifact of the C++/Delphi implementation — uninitialized
   memory, an incidental effect of `int` narrowing, a scoping accident — and the port's current
   divergence should stay, documented rather than "fixed"), **PORT-ONLY BUG** (a defect with no legacy
   counterpart to compare against at all — fix on its own merits), or **NEEDS_MAINTAINER_DECISION**
   (genuine judgment call, or deferred until a real use case exists). Wave 3 also caught several outright
   errors in the Wave 1/2 writeup — wrong severities, a wrong suggested fix that would have introduced a
   *new* bug (#28), mis-scoped findings (#27), and findings framed as "legacy divergences" that have no
   legacy counterpart at all (#36-38) — all corrected below.

No files were modified at any stage. No finding is reported as "confirmed" unless a second, independent
agent verified the underlying math/logic itself.

Severity vocabulary (extended to cover SSTV's image-decode domain, not just audio): **silent numeric
drift**, **visible artifact risk** (wrong pixels/image), **audible artifact risk** (wrong/artifacted
audio), **crash risk**.

## Claims investigated and refuted (do not re-investigate)

Raised in Wave 1, refuted in Wave 2, and independently **sanity-checked again in Wave 3** (all four
refutations were re-confirmed correct — no re-opening needed):

| Original claim | Why refuted | What's actually true instead |
|---|---|---|
| Native audio capture ring buffer silently drops samples on overrun where legacy hard-stops | Legacy **also** loses data on overrun (device close + restart), and loses *more* of it (whole in-flight FIFO plus restart time) than the port's per-callback drop. | Diagnostics gap, not silent corruption: legacy exposes overrun loss to the decoder live (`m_Lost`/`InfoRxLost`); the port only exposes a poll-able counter plus a dispose-time log. |
| `AnalogFmSstvEncoder` carrying full double-precision Hz to the oscillator vs legacy's int-Hz + 12-bit mask | Every currently-registered mode's frequencies are already integer-valued by construction — zero numeric effect today. | Forward-looking risk only: nothing *enforces* integer quantization at the oscillator boundary for a future fractional-Hz mode. |
| FFT twiddle-factor float recurrence causes "elevated noise floor" | The recurrence re-seeds per butterfly group, bounding the error to ≈-90..-110 dB — below any waterfall's displayed range. | Real but cosmetic; see finding #17. |
| Missing NaN protection is a legacy-vs-port asymmetry | Legacy's own NaN guard is equally porous to NaN. | The real gap is the missing *upper* clamp/Inf guard, not a NaN-safety asymmetry; see finding #18. |

## Top priorities (re-ranked after Wave 3)

1. **#26** — Missing TX output bandpass filter. Upgraded by Wave 3 to a real transmit spectral-purity /
   RF-hygiene concern, not just a golden-vector nit — legacy has it on by default for a reason.
2. **#27** — Robot 36 line-0 chroma defaults to the wrong color-space domain (guaranteed visible on every
   image). One-line fix, scope corrected to Robot 36 only.
3. **#1** — AFC-driven tone resonators never retune. Confirmed deliberate legacy design; degrades exactly
   the off-frequency reception AFC exists to correct.
4. **#7 / #9 / #8** — Three independent, all-`MATCH_LEGACY` SlantTracker bugs (jitter-gate off-by-one,
   no post-commit reset, wrong PD120/180/240 threshold) that compound on any signal needing more than one
   auto-slant correction.
5. **#28** — Missing int-truncation before YCbCr→RGB conversion. Fix approach corrected in Wave 3 — the
   original suggested fix would have introduced a new bug by truncating in the wrong domain.
6. **#2 / #3 / #4** — AFC sign error, zero-Hz lock-average seed, and correction-gating bug. All three
   independently confirmed `MATCH_LEGACY` with strong supporting derivations (notably #2's "128 units =
   exactly one luma level" dimensional coincidence).
7. **#34** — `int` overflow after ~13.5h continuous RX. Pure port bug, unrelated to legacy fidelity,
   trivial fix (widen to `long`), real for unattended monitoring use.
8. **#6** — AGC state not reset on TX/RX transition. Confirmed deliberate legacy hygiene the port should
   replicate.
